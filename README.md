# Maximka

## Контракт страницы каталога квартир

Страница `pages/catalog.html` получает выдачу квартир из JSON API. Клиентская часть интеграции реализована; от бэкенда требуется endpoint по описанному ниже контракту. Текущие карточки в `pages-data/catalog.js` являются fallback-разметкой и после успешного ответа API не считаются источником актуальной цены, статуса бронирования или количества квартир.

### Общая схема интеграции

- Endpoint и размер порции задаются через `catalog.apiUrl` и `catalog.pageSize` в `pages-data/catalog.js`; они выводятся как `data-url="/api/v1/apartments"` и `data-page-size="15"` на `.js-apartment-catalog`.
- Если `data-url` отсутствует, компонент работает со статичной разметкой, как сейчас. Это сохраняет локальную разработку и graceful degradation.
- При наличии `data-url` первая порция запрашивается сразу во время инициализации. Пока ответ не получен или если запрос завершился ошибкой, уже отрисованные статичные карточки остаются на странице.
- Фильтрация, сортировка и переключатель «Не показывать забронированные» делают новый запрос и полностью заменяют только квартирные карточки.
- Кнопка «Показать еще» запрашивает следующую порцию и добавляет карточки в существующую выдачу.
- Карточки заявки и ипотеки являются контентными блоками фронтенда. API их не возвращает и не учитывает в `total`, `returned` или `remaining`.

Vite-компиляция Handlebars выполняется только во время сборки, поэтому partial `partials/components/apartment-card.html` нельзя вызвать в браузере напрямую. Для ответов API реализован безопасный DOM-renderer `src/js/utils/renderApartmentCard.ts`, повторяющий структуру partial без вставки данных через `innerHTML`. Каноническим считается описанный ниже JSON DTO; HTML из API возвращать не нужно.

### Endpoint выдачи

```text
GET /api/v1/apartments
Accept: application/json
```

Один endpoint используется и для новой выборки, и для следующих страниц. Все массивы передаются повторяющимися query-параметрами, а не строкой через запятую.

Пример запроса:

```text
GET /api/v1/apartments?rooms=studio&rooms=1&priceMin=3678809&priceMax=15500000&areaMin=22&areaMax=68&entrances=1&entrances=3&entrances=4&floorMin=2&floorMax=13&floorOptions=not-first&features=bathroom-window&features=spacious-kitchen&hideReserved=true&sort=price-asc&limit=15
```

Параметры:

| Query-параметр | Тип | Соответствие интерфейсу | Правила |
| --- | --- | --- | --- |
| `rooms` | `string[]` | `input[name="rooms"]` | Допустимы `studio`, `1`, `2`, `3`. Несколько значений объединяются по OR. Параметр не передан — любое количество комнат. |
| `priceMin`, `priceMax` | integer | Диапазон «Стоимость, ₽» | Цена в целых рублях, без пробелов и символа валюты. Границы включительно. |
| `areaMin`, `areaMax` | number | Диапазон «Площадь, м²» | Площадь в м², границы включительно. Десятичный разделитель в URL — точка. |
| `entrances` | `string[]` | `input[name="entrances"]` | Номера подъездов. Несколько значений объединяются по OR. |
| `floorMin`, `floorMax` | integer | Диапазон «Этаж» | Границы включительно. |
| `floorOptions` | `string[]` | `input[name="floor-options"]` | `not-first` исключает первый этаж, `not-last` — последний. Между выбранными значениями действует AND. |
| `features` | `string[]` | `input[name="features"]` | Системные id преимуществ. Квартира должна содержать все выбранные преимущества, то есть между значениями действует AND. |
| `hideReserved` | boolean | `input[name="hide-reserved"]` | Передается как `true`, если забронированные нужно исключить. При `false` параметр можно не передавать. |
| `sort` | enum | `input[name="catalog-sort"]` | `price-asc`, `price-desc`, `area-asc`, `area-desc`. По умолчанию `price-asc`. |
| `limit` | integer | Размер порции | По умолчанию `15`, допустимо `1…50`. |
| `cursor` | string | Следующая порция | Непрозрачное значение из `pagination.nextCursor`. Для первой страницы не передается. |

Поля диапазонов в текущем HTML не имеют `name`: интеграционный код читает числовые значения из `.js-catalog-range-min` и `.js-catalog-range-max` и явно переводит их в `priceMin/priceMax`, `areaMin/areaMax` и `floorMin/floorMax`. Отформатированные текстовые поля (`3 678 809`) в запрос не отправляются.

Неизвестное значение enum, отрицательная цена, `min > max`, невалидный `cursor` и `limit` вне диапазона считаются ошибкой валидации, а не молча исправляются бэкендом.

### Логика применения фильтров

- Кнопка «Показать варианты» применяет текущее состояние формы. На мобильном после успешного ответа модальное окно фильтра закрывается.
- Смена сортировки и `hideReserved` применяются сразу.
- `reset` возвращает значения из исходной конфигурации фильтров и делает запрос первой страницы.
- Любое изменение фильтров или сортировки сбрасывает `cursor`, заменяет выдачу и прокручивает страницу к началу результатов только после успешного ответа.
- Query-параметры активных фильтров, кроме `cursor` и `limit`, дублируются в URL страницы через `history.replaceState`. При прямом открытии такой ссылки состояние контролов восстанавливается до первого запроса.
- Пустой массив параметра не отправляется. Полные диапазоны можно не отправлять, но фронтенд и бэкенд должны использовать одинаковые значения `facets.*.min/max` по умолчанию.
- `total` в ответе — единственный источник текста «Найдено N квартир». Текущие `catalog.count`, `catalog.totalCount` и `catalog.moreCount` после подключения API заменяются данными ответа.

#### Поля карточки

- `id` — обязательный стабильный id, уникальный во всей выдаче. Используется в `id="apartment-features-{id}"`, поэтому допустимы только латинские буквы, цифры, `_` и `-`.
- `href` — обязательный внутренний или абсолютный URL детальной страницы.
- `title`, `area`, `floor`, `price` — обязательные готовые к показу строки. Числа форматируются с учетом русской локали.
- `images` — минимум одно изображение. `src`, положительные `width/height` и содержательный `alt` обязательны. Растровые локальные изображения передаются в `webp`; `className` допускает только известные фронтенду модификаторы.
- `hasMultipleImages` — `true` только при `images.length > 1`. Можно вычислять на фронтенде, но если поле передается, оно должно совпадать с массивом.
- `oldPrice`, `discount` и `discountIcon` передаются вместе, когда есть скидка. `discountIcon` содержит внутренний или абсолютный URL иконки; frontend не задаёт его самостоятельно. Если скидки нет, все три поля равны `null` или отсутствуют.
- `mortgage` — готовая строка платежа. Текущий шаблон показывает либо `mortgage`, либо блок `oldPrice/discount`. Если нужны оба блока одновременно, сначала требуется изменение верстки.
- `features` — короткий набор меток, постоянно видимый в карточке; сейчас ожидается не более двух.
- `allFeatures` — полный набор меток для popover. `featuresRemaining` равен `max(allFeatures.length - features.length, 0)`.
- Если `featuresRemaining` равен `0`, renderer не создает кнопку `.js-apartment-features-toggle` и пустой popover.
- `reserved: true` делает карточку некликабельной, добавляет `is-reserved`, `aria-disabled="true"`, статус «Забронировано» и `js-reserved-apartment` на родительский `li`.

`modifier` не входит в API: для элементов каталога frontend всегда задает `modifier: "catalog"` сам.

#### Пагинация

- `returned` — количество квартир именно в текущем ответе и должно равняться `items.length`.
- `total` — полное количество квартир по активным фильтрам, без учета `cursor` и `limit`.
- `remaining` — сколько квартир останется не загружено после применения текущего ответа.
- `nextCursor` — непрозрачный cursor следующей порции. Фронтенд не разбирает и не изменяет его.
- `hasMore` равен `nextCursor !== null && remaining > 0`.
- При `hasMore: false` сервер возвращает `nextCursor: null`, `remaining: 0`, а кнопка «Показать еще» скрывается.
- Текст кнопки строится как `Показать еще min(limit, remaining до запроса) из remaining до запроса`. После ответа значения пересчитываются.
- Cursor должен фиксировать сортировку и позицию в выборке. Для равных цены или площади бэкенд обязательно добавляет стабильную сортировку по `id`, чтобы между порциями не было дублей и пропусков.
- Cursor принадлежит конкретному набору фильтров и сортировке. Фронтенд никогда не использует старый cursor после их изменения.

Cursor-пагинация предпочтительнее `page/offset`, потому что цена и статус бронирования могут измениться между запросами. Если cursor устарел, API возвращает `409 CURSOR_EXPIRED`; фронтенд показывает ненавязчивое сообщение и заново загружает первую страницу с текущими фильтрами.

#### Facets и конфигурация фильтра

`facets` возвращаются на первой странице каждого нового набора фильтров. Для запроса с `cursor` их можно не передавать.

- `price`, `area`, `floor` задают абсолютные границы контролов.
- Элементы `rooms`, `entrances`, `features` содержат системное `value` и количество доступных квартир `count`.
- `label` можно передавать для справочных целей, но текущий frontend не создает новые контролы из `facets`: системные `value` должны соответствовать вариантам, уже отрисованным из `pages-data/catalog.js`.
- Значение с `count: 0` становится disabled, кроме уже выбранного: выбранное значение должно оставаться доступным, чтобы пользователь мог его снять.
- `count` считается с учетом остальных активных групп фильтров, но без собственной группы. Это позволяет пользователю видеть, сколько результатов добавит или оставит конкретный вариант.
- Набор системных `value` должен быть стабильным. Изменение подписи не должно менять URL фильтра.

Если состав и границы фильтров не меняются из CMS, допустимо оставить их в `pages-data/catalog.js` и не возвращать `facets`. В этом случае API все равно обязан вернуть `pagination.total`, а frontend не показывает счетчики возле вариантов.

### Подгрузка следующих карточек

1. Frontend сохраняет `pagination.nextCursor` последнего успешного ответа.
2. По клику блокирует кнопку от повторного нажатия, выставляет ей `aria-busy="true"` и делает тот же GET с текущими фильтрами, `sort`, `limit` и `cursor`.
3. Полученные квартирные `li` добавляются в сетку. Уже загруженные `id` проверяются и не дублируются.
4. Контентные карточки расставляются заново: форма остается после восьмой квартиры, ипотечный блок — после последней загруженной квартиры. Они не сортируются и не учитываются в пагинации.
5. Обновляются `nextCursor`, подпись/видимость кнопки и интерактив карточек.
6. Фокус остается на кнопке «Показать еще»; новые карточки не перехватывают его. Отдельный `aria-live`-статус сообщает «Загружено еще N квартир».

На время запроса сетка сохраняется. Для новой выборки можно показывать overlay/skeleton, но нельзя сначала очищать успешную выдачу: при ошибке пользователь должен сохранить предыдущий результат.

### Инициализация интерактива динамических карточек

За галереи изображений и popover преимуществ отвечает `ApartmentRecommendations`, который инициализируется на `.js-apartment-recommendations`. После каждого успешного `replace` или `append` `ApartmentCatalog` вызывает публичный `refresh()`: старые карточечные обработчики снимаются, коллекции toggles/галерей собираются заново, а document-listeners не дублируются.

Дополнительная инициализация для `<img loading="lazy">` и SVG `<use>` не нужна. Форму `.contact-request-card` не следует удалять и создавать заново при фильтрации или дозагрузке; тогда существующие `AJAXForm`, маска телефона и валидатор сохранят свои обработчики.

### Замена, сортировка и контентные карточки

При наличии `data-url` смена сортировки всегда запрашивает первую порцию у сервера. Метод `ApartmentCatalog.sortApartments()` используется только в статичном fallback-режиме без API и не влияет на серверную выдачу.

При замене выдачи удаляются только `li`, содержащие `.apartment-card--catalog`. Элементы `.apartment-catalog__item--contact` и `.apartment-catalog__item--mortgage` сохраняются и затем перемещаются в нужные позиции. При пустой выдаче оба контентных блока скрываются, а вместо сетки показывается состояние «По выбранным параметрам квартир не найдено».

### Состояния запроса и конкуренция

- Для новой фильтрации frontend отменяет предыдущий запрос через `AbortController`.
- Ответ дополнительно проверяется монотонным номером запроса: более старый ответ никогда не заменяет более новый, даже если отмена не успела сработать.
- Во время load more допускается только один запрос. Изменение фильтра отменяет load more и начинает новую выборку без cursor.
- Корню результатов выставляется `aria-busy="true"`; после завершения или ошибки атрибут снимается.
- Статус `reserved` и цена берутся только из последнего ответа API. Frontend их не кэширует дольше текущей страницы.
- Рекомендуемый `Cache-Control` для выдачи: `no-store` или короткий private cache, согласованный с допустимой задержкой обновления бронирований.

### Пустой результат и ошибки

Пустая успешная выдача:

```json
{
  "items": [],
  "pagination": {
    "limit": 15,
    "returned": 0,
    "total": 0,
    "remaining": 0,
    "nextCursor": null,
    "hasMore": false
  }
}
```

Формат ошибки:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Некорректные параметры фильтра",
    "fields": {
      "priceMin": "Значение должно быть целым положительным числом"
    }
  }
}
```

Ожидаемые статусы:

- `400 VALIDATION_ERROR` — неверные query-параметры;
- `409 CURSOR_EXPIRED` — cursor больше нельзя продолжить;
- `429 RATE_LIMITED` — слишком много запросов;
- `500 INTERNAL_ERROR` или `503 SERVICE_UNAVAILABLE` — временная серверная ошибка.

При ошибке первой страницы frontend сохраняет текущие карточки и показывает сообщение с кнопкой «Повторить». При ошибке load more уже загруженные карточки остаются, cursor не меняется, кнопка разблокируется и повторяет тот же запрос. Технический `message` сервера не вставляется пользователю как HTML.

### Требования безопасности и целостности

- Текстовые поля карточки вставляются через `textContent`, URL — через проверенные DOM-свойства/атрибуты. Данные API не передаются напрямую в `innerHTML`.
- Бэкенд не должен отдавать JavaScript, inline-обработчики или произвольные CSS-классы.
- В одном ответе не может быть повторяющихся `items[].id`.
- `pagination.returned === items.length`, `remaining >= 0`, `total >= returned`.
- При `reserved: true` ссылка квартиры не рендерится, даже если `href` присутствует.
- API отвечает в UTF-8 с `Content-Type: application/json`.

### Минимальный сценарий приемки

1. Открытие прямой ссылки с фильтрами восстанавливает UI и загружает корректную первую порцию.
2. Submit фильтра заменяет квартиры, обновляет `total` и сбрасывает cursor.
3. Сортировка применяется ко всей серверной выдаче, а не только к видимым карточкам.
4. `hideReserved=true` не возвращает забронированные квартиры.
5. Несколько кликов «Показать еще» не дают дублей, сохраняют порядок и в конце скрывают кнопку.
6. Галерея и popover работают и у исходных, и у дозагруженных карточек.
7. Форма заявки продолжает валидироваться и отправляться после фильтрации и дозагрузки.
8. Пустой ответ, `400`, `409` и `500` показывают предусмотренные состояния без потери уже успешной выдачи.

## Контракт секции "Ход строительства"

Секция `partials/sections/progress.html` может работать в статичном режиме или загружать фотографии по JSON.

### Подключение API

Чтобы включить загрузку с бэка, нужно добавить атрибут `data-url` на корневой элемент секции:

```html
<section class="progress js-progress" data-url="/api/progress" aria-labelledby="progress-title">
```

Если `data-url` отсутствует, компонент не делает запросы и оставляет текущую статичную разметку.

### Запрос

Компонент делает `GET`-запрос на URL из `data-url`:

```text
GET /api/progress?year=2026&quarter=2
Accept: application/json
```

Параметры:

- `year` — выбранный год, строка из значения `input[name="progress-year"]`.
- `quarter` — выбранный квартал, строка из значения `input[name="progress-quarter"]`.

Запрос выполняется при инициализации секции и при каждом изменении фильтров. Предыдущий незавершенный запрос отменяется.

### Ответ

Основной ожидаемый формат:

```json
{
  "items": [
    {
      "image": "/images/progress/1.webp",
      "width": 1410,
      "height": 1030,
      "alt": "Строительная площадка",
      "year": "2026",
      "quarter": "2"
    }
  ]
}
```

Также поддерживается короткий формат, где корнем ответа является массив:

```json
[
  {
    "image": "/images/progress/1.webp",
    "width": 1410,
    "height": 1030,
    "alt": "Строительная площадка"
  }
]
```

Поля элемента:

- `image` — обязательный путь к изображению.
- `width` — обязательная ширина изображения.
- `height` — обязательная высота изображения.
- `alt` — обязательный alt-текст.
- `year` — необязательный год, сохраняется в `data-year`.
- `quarter` — необязательный квартал, сохраняется в `data-quarter`.

Если `items` пустой или ответ не содержит валидных элементов, секция показывает текст `progress.emptyText`, скрывает стрелки и scrollbar слайдера.

## Контракт секции "Инфраструктура на карте"

Секция карты рендерится из данных `infrastructure` в контексте страницы. Сейчас пример лежит в `pages-data/home.js`, но с бэка ожидается такая же структура: настройки карты, объект ЖК, категории фильтров и массив точек.

### Формат данных

```json
{
  "infrastructure": {
    "label": "Максимум комфорта",
    "title": "ЖК «Максима» расположен...",
    "description": "До метро — 12 минут пешком...",
    "cta": {
      "label": "Назначить встречу",
      "href": "#request-dialog"
    },
    "ctaMobile": {
      "label": "Выбрать квартиру",
      "href": "#layouts"
    },
    "defaultCategoryLabel": "Вся инфраструктура",
    "filtersLabel": "Фильтр инфраструктуры на карте",
    "map": {
      "apiKey": "YANDEX_MAPS_API_KEY",
      "ariaLabel": "Карта инфраструктуры рядом с ЖК Максима",
      "center": "49.0992,55.8605",
      "zoom": "15.6",
      "complex": {
        "title": "ЖК «Максима»",
        "coordinates": "49.10198,55.85944",
        "contour": "49.10134,55.85964;49.10215,55.85975;49.10229,55.85952",
        "icon": "/images/infrastructure/complex-marker.svg"
      }
    },
    "categories": [
      {
        "id": "school",
        "label": "Школы",
        "icon": "/images/infrastructure/school.svg"
      }
    ],
    "points": [
      {
        "category": "school",
        "title": "Лицей № 145",
        "description": "Физико-математический лицей",
        "address": "ул. Дементьева, 16",
        "distance": "800 м, 10 мин",
        "coordinates": "49.10193,55.85762",
        "icon": "/images/infrastructure/school.svg"
      }
    ]
  }
}
```

### Поля карты

- `cta` — кнопка на десктопе.
- `ctaMobile` — отдельная кнопка под картой на мобильной версии.
- `map.apiKey` — ключ JavaScript API Яндекс.Карт v3.
- `map.center` — центр карты в формате `долгота,широта`.
- `map.zoom` — стартовый zoom, строка или число.
- `map.complex.coordinates` — координаты метки ЖК в формате `долгота,широта`.
- `map.complex.contour` — контур участка/дома: пары `долгота,широта`, разделенные `;`. Последняя точка может повторять первую, чтобы замкнуть контур.
- `map.complex.icon` — SVG-иконка метки ЖК.

### Категории

`categories` управляют левым фильтром карты на десктопе и выпадающим списком на мобильной версии.

- `id` — системный идентификатор категории. Должен совпадать с `points[].category`.
- `label` — текст в фильтре.
- `icon` — SVG-иконка категории.
- `active` — необязательное поле. Для пункта "Вся инфраструктура" можно передать `true`.
- `defaultCategoryLabel` — начальная подпись мобильного селекта. Обычно совпадает с `label` активной категории.

Для общего фильтра используется категория:

```json
{
  "id": "all",
  "label": "Вся инфраструктура",
  "icon": "/images/infrastructure/all.svg",
  "active": true
}
```

### Точки инфраструктуры

- `category` — обязательный id категории.
- `title` — обязательное название точки.
- `coordinates` — обязательные координаты в формате `долгота,широта`.
- `icon` — обязательная SVG-иконка маркера.
- `description` — необязательная строка для второй строки поповера.
- `address` — необязательный адрес.
- `distance` — необязательная дистанция/время.

Поповер показывает `title` и вторую строку. Если `description` заполнен, используется он. Если `description` пустой, вторая строка собирается из `address` и `distance`.

### Важные требования

- Координаты всегда передаются как `longitude,latitude`, не наоборот.
- Иконки должны быть SVG и доступны по публичному URL.
- Ключ Яндекс.Карт должен разрешать домены, на которых запускается сайт. Для локальной разработки обычно нужны `http://127.0.0.1:5173/*` и `http://localhost:5173/*`.
- Стилизация карты подключается из `src/js/data/infrastructureMapCustomization.json`.
